# v0.33.0 Handoff — Visual Guidance / TL;DR Mode

## Product objective

v0.33 makes Blueprint easier to understand at a glance without removing its depth.

The guiding rule is:

> **Show the next useful thing strongly; explain unfamiliar things at the point of use; let experienced users collapse explanation without losing control.**

## New reusable primitives

### `GuidanceProvider`
Carries the display-only `tldrMode` preference through the app.

### `GuidanceToggle`
Accessible desktop/mobile toggle using `aria-pressed`. TL;DR defaults Off and persists under `blueprint:tldr-mode:v1`.

### `ConceptInfo`
Circular `i` trigger built with native details/summary semantics. Use only when a concept is likely to be unfamiliar or its meaning has important authority implications.

Do **not** put an info icon beside every label. The cue loses value when everything is marked unfamiliar.

### `TldrSummary`, `TldrOnly`, `VerboseOnly`
Use these to create an alternate concise reading path. TL;DR should be authored, not generated by blindly clipping text.

## TL;DR safety rule

TL;DR may hide or replace:
- background explanation;
- rationale anatomy;
- repeated metadata;
- secondary examples;
- low-frequency supporting detail.

TL;DR must never hide:
- blockers;
- unresolved required/recommended decisions;
- readiness state;
- explicit Include / Not needed controls;
- primary navigation/next action;
- build/export actions;
- visual approval state/action;
- warnings that materially affect implementation authority.

## Visual cue system

Setup uses a three-step orientation path:
1. **Describe** — give Blueprint enough context.
2. **Resolve** — settle important surfaced decisions.
3. **Tune if needed** — use deeper controls only when the default/recommendation is not enough.

Severity rails distinguish required/blocking attention from recommendations without relying on prose alone.

## Concept vocabulary

Visual Studio keeps a reusable `visualConceptHelp` map for terms such as Design autonomy, Visual originality, Signature brand moment, Information density, Grid character, Section strategy, and related controls.

For App Setup, Standard/Advanced settings and selected technical terms may derive their explainer from catalog description/caution text. This keeps the explanation near the canonical setting definition instead of duplicating content.

## Scope-authority boundary

All v0.33 guidance code is presentation-only. `Guidance.tsx` owns no config setter and no scope mutation function.

Concept explainers explain existing authority; they do not create authority. TL;DR changes visibility only; it does not change the compiled project.
